# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this project is

A VLM (Vision Language Model) benchmarking workbench. Users upload images, select a provider (Anthropic, Google Gemini, AWS Bedrock, Ollama), pick or author a "skill" (system prompt + task template + few-shot examples), and run multi-model comparisons. Results are streamed back over SSE and persisted in Postgres. Images are stored in an S3-compatible bucket (MinIO in dev, GCS/S3 in prod).

## Development commands

```bash
# One-command local stack (hot reload for both backend and frontend)
cp .env.example .env    # fill in provider keys first
make dev                # starts Postgres + MinIO + backend (8080) + frontend (5173)

make down               # stop (keeps volumes)
make down-clean         # stop and wipe Postgres + MinIO volumes

# Individual services (requires local Postgres + MinIO already running)
make backend            # uv run uvicorn backend.main:app --reload --port 8080
make frontend           # npm run dev

# Database migrations
make migrate            # apply all pending Alembic migrations
make migration MSG="add foo column"   # generate a new autogenerated migration

# Frontend
make type-check         # npx tsc --noEmit
cd frontend && npm run lint    # eslint

# Build + deploy (GCP Cloud Run)
make build              # docker build production image
make push               # build + push to Artifact Registry
make deploy             # push + gcloud run deploy
```

Local URLs: frontend `http://localhost:5173`, backend API `http://localhost:8080`, MinIO console `http://localhost:9001` (`minioadmin` / `minioadmin`), Postgres `postgres://vlm:vlm@localhost:5433/vlm`.

Default dev credentials (from docker-compose): `admin@local` / `admin`. Set `AUTH_DISABLED=true` to skip login entirely.

## Architecture

```
Browser (React + Vite + Zustand)
    │  fetch / EventSource (SSE)
    ▼
FastAPI backend (backend/main.py)
    ├── api/routers/         REST endpoints (auth, benchmark, chats, comparisons,
    │                        images, models, skills, workspaces)
    ├── providers/           VLMProvider ABC + implementations (claude, gemini,
    │                        bedrock, ollama)
    ├── graph/               LangGraph pipeline (preprocess → build_prompt →
    │                        invoke_model → record_metrics)
    ├── models/              SQLAlchemy ORM models (all in `vlm` Postgres schema)
    ├── core/                config, database, auth, storage, skills_loader
    └── skills/              Bundled YAML skills (bundled)
    └── data/skills/         User-created YAML skills (runtime)
    │
    ├── Postgres (asyncpg + SQLAlchemy async)
    └── S3-compatible storage (aioboto3) — MinIO locally, GCS/S3 in prod
```

**Benchmark request flow** (`POST /api/benchmark/run`):
1. Resolve workspace/chat (creates chat row if `chat_id` is null).
2. Fetch image bytes from S3 in parallel.
3. Snapshot the active skill into `skill_snapshots` (so history reflects what was used).
4. Insert `messages` and `message_images` rows with frozen annotations.
5. Stream tokens from the provider via `VLMProvider.astream_vision()`; write assistant message row on completion.
6. Emit a final SSE event with `chat_id` + `message_id`.

**LangGraph pipeline** (`graph/benchmark_graph.py`): stateless pipeline used for prompt construction — resize images to max 1568px (Anthropic limit), apply Jinja2 skill template, prepend few-shot examples, then call the provider. The compiled graph is a module-level singleton.

**Skills** (`backend/skills/` + `data/skills/`): YAML files with `name`, `system_prompt`, `task_template` (Jinja2), `few_shot_examples`, and `metrics`. Bundled skills ship with the repo; user skills are written to `data/skills/` at runtime and persist across restarts via the mounted volume.

**Auth**: Argon2 password hashing, server-side sessions (signed cookie via `itsdangerous`). `AUTH_DISABLED=true` bypasses all auth — safe only for local/solo deployments.

**Migrations**: Alembic (`backend/migrations/`), run automatically at app startup via `asyncio.to_thread`. Schema lives in the `vlm` Postgres schema. Generate new migrations with `make migration MSG="..."`.

**Production**: Single Docker image serves both the FastAPI backend and the built React SPA (frontend `dist/` is mounted under `/assets` and `/*` falls back to `index.html`). Env vars only differ between environments. See `DEPLOY.md` for GCP Cloud Run setup.

## Key conventions

- All DB operations use SQLAlchemy async sessions. Use `get_session` (FastAPI dependency) in request handlers; use `SessionLocal()` context manager in background tasks.
- All table models inherit from `backend/models/base.py:Base` and live in the `vlm` schema. UUIDs are the standard PK type.
- Provider implementations must subclass `VLMProvider` and implement `list_models()` and `astream_vision()`. Per-request API key overrides are passed in the `BenchmarkRequest` body and never persisted.
- Frontend state management uses Zustand stores (`frontend/src/stores/`); API calls go through typed client functions in `frontend/src/api/`.
- The `S3_PUBLIC_ENDPOINT_URL` env var is what the browser uses for presigned image reads — in dev it must be `http://localhost:9000` even though the backend talks to `http://minio:9000`.
